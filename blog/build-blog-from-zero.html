从零搭一个 GitHub Pages 博客：借 AI 一条路，纯手搓一条路

2026-10-31 教程

这篇教程的目标很具体：把「dabai-abc.github.io」这个站从头搭一遍。你现在看到的首页、博客列表、文章页、资源页，都是下面这些步骤的产物。

先把前提说清楚

GitHub Pages 是纯静态托管：它只把仓库里的文件原样发给浏览器，不执行后端代码，没有数据库，也没有登录。所以它能做的事是「展示」，不能做「管理」。这一点决定了后面所有的设计：发文 = 往仓库里写文件再推送，没有别的路径。

另外两个成本事实，早点知道能少走弯路：

  • 公开仓库的 Pages 完全免费，流量也不额外收费。
  • 私有仓库想开 Pages 需要 GitHub Pro。也就是说，别指望用私有仓库来藏内容，真要不公开，得在页面层面做加密（后面路线 A 有一节讲）。

路线 A：借 WorkBuddy 搭

这条路的核心思路是：你负责说清「要什么」，它负责写文件、跑命令、推代码。整个过程中你真正要动手的地方只有三个——装软件、点一次 GitHub 网页上的开关、以及看结果。

第 1 步 · 装 WorkBuddy（唯一）

没有替代方案，这条路就是靠它。装桌面端，登录，然后给它一个空目录当工作区（比如 ~/github），授权它读写这个目录、执行终端命令。

授权范围建议只给这个目录，不要给整个家目录——后面它会跑 git、写文件、起本地服务器，权限收窄一点更安心。

第 2 步 · 注册 GitHub 账号并想好站点地址（唯一）

用户名一旦定下来，免费版域名就跟着定了：https://用户名.github.io。改用户名会导致旧地址失效，所以第一次就取个能长期用的。

第 3 步 · 建仓库（两种做法）

仓库名有硬性要求：必须是 用户名.github.io，一字不差，包括大小写。名字不对的话，Pages 会把它当成「项目页」，地址变成 用户名.github.io/仓库名/，多一层路径，站内所有绝对路径全要改。

做法一，你自己在网页上建：github.com → New repository → 名字填 用户名.github.io → Public → 不要勾选任何初始化文件 → Create。

做法二，让 WorkBuddy 代跑：

gh auth login          # 只需要做一次
gh repo create 用户名.github.io --public

gh 是 GitHub 官方命令行工具，没装的话先 brew install gh。两条路结果一样，做法二省一次手动点击，但 gh auth login 的浏览器授权还是得你本人确认。

第 4 步 · 让 WorkBuddy 生成首页

这是整条路里最关键的一次对话。提示词写得越具体，返工越少。可以直接用这段：

在 ~/github 下新建目录 用户名.github.io，里面放一个 index.html：
1. 纯静态单文件，样式写在 <style> 里，不引用任何外部 CDN 和字体
2. 所有颜色、圆角、字体定义成 :root 里的 CSS 变量，方便以后改主题
3. 支持系统暗色模式（prefers-color-scheme）
4. 内容区最大宽度 880px，手机上不出横向滚动条
5. 结构：大标题 + 一句话简介 + 三张项目卡片 + 博客入口 + GitHub 链接 + 页脚年份自动更新
6. 顺便 git init，第一个提交叫 init

说完它会一次性把文件写好、git init、提交。你要做的是看一眼产出：文件在哪、变量是不是真的提出来了、有没有偷偷引外部字体。

如果对样式不满意，别自己改 CSS，直接说「标题渐变改成从蓝到紫，卡片 hover 上浮 2px」——它改得比你手改快。

第 5 步 · 加博客区

首页有了，再让它长出一个博客。这一步产出的东西比首页多，值得说细一点：

给这个站加一个博客区：
1. 新建 assets/blog.css，作为博客和文章页共用的样式，配色沿用首页的 CSS 变量
2. 新建 blog/index.html，文章列表页
3. 新建 templates/post-template.html，作为以后新文章的空模板
4. 先放一篇示例文章 blog/welcome.html，并从首页链过去
5. 所有站内链接用绝对路径（/blog/、/assets/blog.css），不要用相对路径

第 5 条别省。绝对路径的意思是无论从 /blog/ 还是 /blog/xxx.html 打开，样式都指向同一个文件；相对路径在子目录里会断。

做完之后目录长这样：

用户名.github.io/
├── index.html
├── assets/
│   └── blog.css
├── blog/
│   ├── index.html
│   └── welcome.html
└── templates/
    └── post-template.html

第 6 步 · 本地预览（唯一）

只能用「起一个本地 HTTP 服务器」这一种方式，双击 HTML 文件不行。原因是站内用的是 /assets/blog.css 这种从根目录算起的绝对路径，file:// 协议下根目录是磁盘根，样式直接 404，页面会变成没有样式的裸文本——很多人到这一步以为样式写崩了，其实只是打开方式不对。

cd ~/github/用户名.github.io
python3 -m http.server 8080

然后浏览器开 http://localhost:8080。macOS 自带 python3，不用装东西。看完记得把服务器停掉，不然 8080 端口一直占着。

第 7 步 · 推上去（唯一动作，授权方式可选）

动作只有一个：git push。第一次推会要求授权，两种方式二选一：

  • Personal Access Token：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained token，只勾选这一个仓库的 Contents 读写权限。推送时用户名填 GitHub 用户名，密码位置粘 token。
  • SSH 密钥：ssh-keygen -t ed25519，把 ~/.ssh/id_ed25519.pub 的内容贴到 GitHub → Settings → SSH keys。配好之后不用再输任何东西。

让 WorkBuddy 推的话，它会自己处理这些，但 token 需要你给一次。给完记得让它把 token 写进系统钥匙串而不是提交进仓库——git remote -v 里如果出现带 token 的地址，那个 token 等于半公开了。

第 8 步 · 开启 Pages（唯一）

这一步没有 API 可替代（虽然 gh api 能调，但新手没必要），只能在网页上点：

仓库 → Settings → 左侧 Pages → Source 选 Deploy from a branch → Branch 选 main、目录选 / (root) → Save。

保存后等一到三分钟。期间可以在仓库的 Actions 标签页看到一条 pages build and deployment 在跑，跑完变绿就上线了。

第 9 步 · 验收

不要凭感觉判断「应该好了」，用地址验：

curl -s -o /dev/null -w '%{http_code}\n' https://用户名.github.io/

返回 200 才算上线。首页 200 但博客 404，通常是第 5 步的目录名或大小写写错了（线上是 Linux，区分大小写；本地 macOS 默认不区分，这类错误本地测不出来）。

验收清单：首页能开、样式在、暗色模式下文字看得清、/blog/ 能开、随便点一篇文章能回来、手机上不出横向滚动条。

第 10 步 · 加一条发文流水线

到这一步站点已经能用了，但发文仍然要手改 HTML：复制模板、改内容、再改一次列表页。一篇两篇还行，十篇之后必然漏。

所以让 WorkBuddy 补一套发布工具。这一段对话我用的是：

给这个博客加一套发文流水线，要求：
1. 写一个 publish.py，只用 Python 标准库，不装依赖
2. 支持 new / post / link / list / build 五个子命令
3. 文章源文件放 content/*.md，开头是 --- 包起来的属性区（title/date/tag/summary/slug）
4. post 命令要能：渲染 Markdown 成 blog/<slug>.html、更新 data/posts.json、git 提交推送
5. 加 .github/workflows/publish.yml，push content/**.md 时自动重建
6. 文章列表页改成读 data/posts.json，用 JS 渲染，这样以后不用手改列表

它最终产出的就是现在这套东西。你可以直接在这个仓库里看源码，关键点有三个：

  • 文章列表不再写死在 HTML 里。blog/index.html 只负责 fetch data/posts.json 然后渲染，发文只改数据。
  • 手机上也能发。content/ 里新建一个 .md，GitHub Actions 会自动重建并提交，不用开电脑。
  • 重复构建不会打乱顺序。posts.json 里除了日期还存了一个写入时刻，同一个日期发两篇也不会乱。

日常发文就一条命令：

python3 publish.py new --title "标题" --tag 教程
python3 publish.py post content/标题.md

第一条要额外说一句：GitHub Pages 没有服务端，所以「加密」只能是「浏览器端解密」。页面本身是公开的密文，谁都可以下载下来离线穷举口令。真要拦住人，得靠有后端的登录系统，而不是静态页加密。

路线 B：不借助 AI，纯手搓

这条路慢，但走完你会知道每个文件为什么存在。全程只用 GitHub 网页、Git 和一个文本编辑器。

第 1 步 · 准备三样东西（唯一）

GitHub 账号、Git、编辑器。Git 用 git --version 验证。编辑器推荐 VS Code，但系统自带的 TextEdit 也能写——保存时注意关掉「智能引号」，它会把你代码里的引号换成中文引号，页面直接坏。

第 2 步 · 建仓库（唯一：仓库名固定）

github.com → New repository → 仓库名填 用户名.github.io → Public → 不初始化任何文件 → Create。

名字必须精确匹配，理由和路线 A 第 3 步一样：名字不对就变成项目页，地址多一层。

第 3 步 · 拿到本地副本（三种做法）

做法一，命令行：

git clone https://github.com/用户名/用户名.github.io.git
cd 用户名.github.io

做法二，GitHub Desktop：File → Clone repository → 选刚建的仓库。

做法三，零安装：不 clone，直接在网页上 Add file → Create new file 把文件一个个建出来。能用，但每改一次都要在网页上提交，文件多了会很累。

第 4 步 · 写首页

在仓库根目录新建 index.html，内容如下。这是一个能直接跑的完整版本，改掉中文的部分就是你自己的站：

<html lang="zh-CN">
<head>

几个容易写错的地方：charset 那行必须在 head 最前面，否则中文变乱码；viewport 那行删了，手机上页面会缩成一小块；box-sizing: border-box 那行删了，加 padding 就会撑出横向滚动条。

第 6 步 · 建文章列表页

新建 blog/index.html：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8" />
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<title>博客 · 你的名字</title>
<link rel="stylesheet" href="/assets/blog.css" />
</head>
<body>
<div class="wrap">
  <nav>
    <a href="/">← 回首页</a>
    <a href="https://github.com/你的用户名">GitHub</a>
  </nav>

  <h1>文章</h1>

  <div style="margin-top:24px">
    <a class="post-item" href="/blog/first.html">
      <span class="date">2026-10-31</span>
      <h2>第一篇文章</h2>
      <p>这里放一句话摘要，让人知道点进去能读到什么。</p>
    </a>
  </div>

  <footer>© 你的名字</footer>
</div>
</body>
</html>

以后每加一篇文章，就在 post-item 那一堆 <a> 里复制一个、放到最上面。这就是纯手搓路线的日常成本：文章和列表永远是两处，必须同步改。

第 7 步 · 写第一篇文章

新建 blog/first.html：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8" />
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<title>第一篇文章 · 你的名字</title>
<link rel="stylesheet" href="/assets/blog.css" />
</head>
<body>
<div class="wrap">
  <nav>
    <a href="/">← 回首页</a>
    <a href="/blog/">博客</a>
  </nav>

  <article>
    <h1>第一篇文章</h1>
    <div class="meta">2026-10-31</div>

    <p>开头一段，说清这篇解决什么问题。</p>

    <h2>小标题</h2>
    <p>正文。段落里的 <code>行内代码</code> 用 code 标签，粗体用 strong。</p>

    <pre><code># 代码块直接放在 pre 里
echo "hello"</code></pre>

    <blockquote>引用或强调。</blockquote>
  </article>

  <footer>© 你的名字</footer>
</div>
</body>
</html>

pre 里面的代码必须把 & 写成 &amp;、< 写成 &lt;，否则浏览器会当成标签解析掉。这是手写 HTML 最烦的一点，也是后来改用 Markdown 的主要原因。

第 8 步 · 放一个空的 .nojekyll（唯一）

在仓库根目录新建一个空文件，文件名就是 .nojekyll，注意前面有个点。

作用：关掉 GitHub 默认的 Jekyll 处理。不关会出两个问题。一是 Jekyll 会忽略所有以下划线开头的文件（_config.yml、_layouts/ 这类），你以后想用就没了。二是 Jekyll 会把 {{ }} 当成模板变量替换，页面里只要出现双花括号就被吃成空白——做模板的时候必然踩到。

命令行建：touch .nojekyll。网页建：Add file → Create new file，文件名填 .nojekyll，内容留空也能提交。

第 9 步 · 提交推送（三种做法）

做法一，命令行：

git add .
git commit -m "first commit"
git branch -M main
git push -u origin main

做法二，GitHub Desktop：左下角填一句摘要 → Commit to main → Push origin。

做法三，网页 Upload files：把整个目录拖进去提交。适合一次传一堆图片，但会丢掉提交粒度。

第 10 步 · 开启 Pages（唯一）

仓库 → Settings → Pages → Source 选 Deploy from a branch → Branch 选 main、目录 / (root) → Save。等一到三分钟。

现象原因处理
打开是 README 内容根目录没有 index.html，Pages 回退去渲染 README补一个 index.html
全程 404仓库名不是 用户名.github.io，或者分支选错改名，或检查 Pages 里的分支与目录
页面出来但没样式链接写成 assets/blog.css 少了开头斜杠，或大小写不符统一改成 /assets/blog.css
改了代码线上没变Pages 的 CDN 有缓存强制刷新，或等两分钟
文件名带下划线的页面 404被 Jekyll 忽略加 .nojekyll
页面局部变成空白内容里有 {{ }} 被 Jekyll 当变量同上，加 .nojekyll
中文图片名打不开URL 被百分号编码，或大小写不一致文件名改成英文小写加连字符

最后一行值得单独记一下：中文文件名能用，但地址会变成一串 %E4%B8%AD...，复制分享很难看，也容易在别的工具里拼错。资源文件统一用英文小写加连字符最省心。

第 12 步 · 以后的日常

手搓路线的发文流程固定三步：

  1. 复制 blog/first.html 成 blog/新文章名.html，改标题、日期、正文
  2. 打开 blog/index.html，在最上面加一个 post-item
  3. git add . && git commit -m "post: 标题" && git push

文章超过十篇之后，第 2 步会开始烦人：很容易忘了加、或者加了链接指错文件。想摆脱这一点，就得回到路线 A 的第 10 步——把列表改成数据驱动，这是这套方案里唯一需要动代码的改造。

两条路的差别在哪

对比项路线 A · 借 WorkBuddy路线 B · 纯手搓
第一次成型半小时左右一到两小时
你实际动手的环节装软件、点 Pages 开关、验收每一步都要动手
发一篇新文章一条命令，或手机上建个 md改两个 HTML 文件
出问题时的排查把报错贴回去让它查自己对照排错表
学到的东西知道系统长什么样、卡在哪知道每个标签为什么这么写

如果只是想有个能写东西的地方，走 A。如果目的是「搞明白静态站是怎么跑起来的」，走 B，而且建议走完 B 之后再回头看 A 的产出，那时候 publish.py 里那些处理中文换行、排序、缓存的细节你会一眼看懂。

两条路最后都会落到同一句话上：这个博客没有后台，它的后台是一个文件加一次推送。想清楚这一点，剩下全是体力活。
