元一岛屿

一个人和内容的小岛。原本是微信小程序，现在后端跑在家里的 NAS 上，浏览器打开就能用：注册、登录、发布、浏览。

它是怎么跑起来的

原项目是 Taro 3.6 + React 写的微信小程序，后端全部依赖微信云开发：35 个云函数、14 个集合。 改造没有重写业务代码，而是在中间垫了一层兼容层。

  • 后端兼容层：用文件型文档存储实现了云数据库那套链式查询接口，把 wx-server-sdk 的引用重定向过去，35 个云函数一行没改就在 NAS 上跑起来了。
  • 前端只动三处：把云调用封装改成走 HTTP、加网页账号登录、补一个登录页。14 个页面本身没动。
  • 部署形态：一个 Node 容器，零 npm 依赖，静态包由同一个进程发出，数据挂载在 ./data，重建容器不丢。
  • 外网通道：Tailscale Funnel 提供 HTTPS 入口。中国大陆家宽没有备案域名，微信正式版那条路走不通，但网页访问不受这个限制。

已知边界

  • 不是微信生态入口：要让小程序正式版直连 NAS，需要 ICP 备案域名 + 固定公网入口，属于资质问题，技术上绕不过。
  • 内容安全检测目前放行：原项目调的 msgSecCheck 现在只记日志，要真检测得配 AppSecret 走微信服务端接口。
  • 数据规模：文件型存储适合个人和小圈子使用，量级上去要换真正的数据库。
